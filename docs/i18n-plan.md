# 多语言（i18n）规划

> 目标：把「设置面板 + 轨道 + 主题名/说明 + 运行期提示」的中文硬编码收口成一套词典，
> 支持 `zh` / `en`，跟随宿主语言实时切换，并用门禁防止回退。
> 不是「全部翻译一遍」：代码注释、CHANGELOG 历史条目、npm 页面的中文说明都不在范围内。

## 1. 现状（不是从零开始）

**已经有一套能用的 i18n，但只覆盖右侧栏轨道**（`src/30-quicknav.js`）：

| 能力 | 位置 | 说明 |
|---|---|---|
| 词典 | `DICT = { zh, en }`（各 **5 键**） | 扁平键，如 `rail.ariaLabel` |
| 取词 | `t(key)` | `DICT[LANG][key] \|\| key` 兜底 |
| 语言来源① | 宿主 locale 服务 | `serviceOf(ctx,'locale').getSnapshot().active` |
| 语言来源② | `navigator.language` 兜底 | **只有 zh\* 算中文，其余一律英文**（面向国际用户） |
| 实时切换 | `ctx.on('locale/change')` + `setLangTick` | 语言变了重渲染 |
| 宿主侧本地化 | `loc.register(NS,{en,zh})` | 让宿主能把槽位标签本地化；注册失败就不声明 `locale` 字段 |

**缺口**（真实量，粗筛非注释行 + 单引号中文字面量）：

| 文件 | 非注释中文行 | 中文字面量 | 主要是什么 |
|---|---|---|---|
| `src/20-tokens-and-panel.js` | 515 | 204 | 设置面板全部文案、按钮、占位符、错误提示、ARIA |
| `src/10-themes.js` | 248 | 36 | 11 套主题的 `label`/`note`、预设名与说明 |
| `src/30-quicknav.js` | 162 | 17 | 轨道词典（已有 zh/en）+ 少量注释 |
| `src/00-core.js` | 21 | 0 | 槽位 `label`（`'Zhuoer 主题'`）等 |

去重后**估计需要 145–170 个键**：面板约 100（含 18 处 `aria-label`）、主题 11 套 + 预设 12 套的
名字与说明 30–45（取决于下面决策点 A）、轨道现有 5、通用按钮约 10。

## 2. 目标 / 非目标

**目标**

1. 面板、轨道、错误提示、ARIA 标签全部走词典，无裸中文；
2. 跟随宿主语言**实时**切换（不刷新）；
3. 未知语言**回落英文**（沿用现有决策）；
4. 门禁可机械判定，防止有人再写裸中文；
5. 主题名可本地化，但**品牌名不翻译**（见 §5 决策点）。

**非目标**

- 不翻译代码注释（中文注释是设计记录，翻成英文反而丢信息）；
- 不翻译 CHANGELOG 历史条目（历史事实不重写）；
- 不做 ICU / 复数 / 性别规则（当前文案没有复数形态，引入只会增加依赖与门禁复杂度）；
- 不新增语言（只做 zh/en 框架，加 `ja` 只需加一份词典）。

## 3. 设计

### 3.1 单一真源：新增 `src/05-i18n.js`

现在 `DICT` 埋在 30-quicknav 里，面板拿不到。改为**独立分片**，在 `build.mjs` 里排在
`00-core` 之后、其余之前（模块级常量，无副作用）：

```
src/00-core.js    → 常量、ensureStyle、基础工具
src/05-i18n.js    → DICT(zh/en) + LANG + t() + 语言解析 + 订阅
src/10-themes.js  → 主题数据（label/note 走键）
src/20-...        → 面板（全部走 t()）
src/30-quicknav   → 轨道（改用共享 t()，删掉本地 DICT）
```

### 3.2 键命名

`<域>.<对象>.<项>`，小驼峰，扁平不嵌套：

```
panel.theme.modeLight / panel.theme.pickHint
theme.zhuoer.label / theme.zhuoer.note
preset.luxe.label / preset.luxe.note
rail.ariaLabel
common.cancel / common.save / common.remove
err.jsonParse / err.bgTooLarge
```

**不改已有的 `rail.*` 键**（宿主已注册，改键等于破坏已发布的宿主侧本地化）。

### 3.3 取词与占位符

`t(key, vars?)`：`{n}` 形式占位，一次 `replace`；缺键返回 `key` 本身（开发期一眼看出漏翻）。
**不做**自动复数、不做 HTML 注入（面板里有富文本需求的地方一律拆成多个键 + 组装）。

### 3.4 语言解析（沿用现有优先级）

```
1) 宿主 locale 服务 active   → zh* 算 zh，其余 en
2) navigator.language        → 同上
3) 默认                       → en
```

监听 `ctx.on('locale/change')` 与注册表订阅，变了就 `bumpLang()`，React 树重渲染（现状已有该机制）。

### 3.5 宿主 locale 命名空间

沿用现状：`loc.register('zhuoerTheme', { en, zh })`，只注册**宿主会读的键**
（槽位 label、引导文案）。注册失败不声明 `locale` 字段（否则宿主判装配失败）。
命名空间从 `rightbarQuicknav` 扩为 `zhuoerTheme` 时**保留旧命名空间注册**，避免轨道标签回退。

## 5. 需要你拍板的两个决策点

**A. 主题名要不要翻译？**

现状是 `Zhuoer 原版红 / Absolutely · 极简 / 灯塔 · Beacon / 手稿 · Manuscript …`——中英混排。

- 方案 A1（推荐）：**名字不翻译，说明翻译**。名字是品牌资产（用户嘴里会说「灯塔」），
  翻译会让人对不上；`note`（一句话风格说明）走词典。
- 方案 A2：名字也做双语（`label` 变成键），代价是搜索/口口相传时两套名字并存。

**B. CHANGELOG 怎么写？**

- 方案 B1（推荐）：**中文为主，最新版本段附一行英文摘要**，历史段不动；
- 方案 B2：每个版本中英双段（维护成本翻倍）；
- 方案 B3：保持中文（CHANGELOG 是给维护者看的，用户看 README 与市场页）。

## 6. 门禁 `verify:i18n` 的设计（P4）

判据要能机械判定，否则「漏翻」永远靠人眼：

1. **键集合相等**：`DICT.zh` 与 `DICT.en` 的键集合必须完全相同（多/少都红）；
2. **占位符一致**：同一键在两语言里的 `{x}` 集合必须相同；
3. **无裸中文**：扫描 `src/**/*.js` 的**字符串字面量**（先剥离注释与正则），出现 CJK 且不在
   白名单 → 红。白名单只允许：`console.warn/error` 的诊断文本、`DICT.zh` 自身、SVG path 等；
4. **键引用存在**：源码里 `t('x')` 的 `x` 必须在两本词典里都存在；
5. **宿主命名空间**：`loc.register` 传的键必须是 `DICT` 的子集。

实现方式与现有门禁一致：`scripts/verify-i18n.mjs` + 字符级扫描（不引依赖），
输出 `OK 词典 zh/en 各 N 键` 或具体违规行号。接入 `verify:all`。

## 8. 风险与回滚

| 风险 | 影响 | 处置 |
|---|---|---|
| 面板文案漏翻 | 英文用户看到中文 | P4 门禁（裸中文检测） |
| 键改名破坏宿主侧本地化 | 轨道标签回退成键名 | 不改已注册的 `rail.*`；改键必须同步 `loc.register` |
| 词典体积 | 包增大（估算 +8–12 KB，可忽略） | 与 4.6 MB 字体相比不构成问题 |
| 语言切换不重渲染 | 切了语言界面不变 | 沿用现有 `setLangTick`；P1 验收加「切换语言面板立即变」 |
| 回滚 | — | 每个阶段独立提交；P4 门禁可单独关闭（但会失去防回退） |
