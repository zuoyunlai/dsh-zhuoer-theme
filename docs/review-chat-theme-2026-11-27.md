## 1. 本轮新增发现：缓存上限会静默吃掉对话生成的底纹（已修）

### 现象

对话里每生成一套带底纹的主题，就往 IndexedDB 写**两张**（明 + 暗，`src/25-chat-card.js:185-191`），
而且**从不删除**（该文件里 `idbDelete` 0 命中）。面板侧删主题时也只删 `key`，不删 `keyLight`
（`src/20-tokens-and-panel.js:2963`）。于是 IDB 里的图只增不减。

而运行期**只同步读内存缓存**（`imageCache.get(specBg.key)`，`:579-580`），IDB **没有按 key 读回的通路**
（`idbGet` grep 0 命中）。这两条一撞上就是致命组合。

### 根因（我自己上一轮引入的）

上一轮的 P3-2 修「缓存无上限」时，我给 `imageCache` 也套了 LRU 上限 `ZR_CACHE_MAX = 12`
（`src/10-themes.js:440` 的 `preloadBgImages` 走 `zrCachePut`）。纯 LRU 淘汰**最旧**的条目——
而最旧的正是最早那几套主题**仍在引用**的图。

实测（20 张 = 10 套主题 × 明暗）：

```
IDB 里 20 张 → 内存只剩 12 条
被淘汰: img_c0, img_c0b, img_c1, img_c1b, img_c2, img_c2b, img_c3, img_c3b
运行期读 imageCache.get('img_c0') → undefined → 该主题底纹静默消失
IDB 有按 key 读回的通路吗：没有 → 被淘汰的图再也回不来
```

**这正是用户说的「聊天窗口能出图，但有点波折」的一个来源**：对话里连续生成几套主题后，
早先那几套的底纹会在刷新后消失——界面不报错、主题还在、只是图没了。

### 修法

`zrCachePut(map, key, value, protectedKeys)` 增加第四个参数：淘汰时**跳过被引用的键**；
`preloadBgImages` 用新增的 `zrReferencedBgKeys()`（扫 `pref.customThemes` 的 `bg.key` 与 `bg.keyLight`）作为保护集。
全部条目都被引用时**停止淘汰**——宁可多占内存，也不让用户的主题少一张图。

### 验收

- 新增 `scripts/test-cache-evict.mjs`（8 例）：无保护时按上限淘汰 / 全被引用时一张不淘汰 / 混合时被引用的留下 / 未超上限不淘汰。
- `npm run verify:all` exit 0；11 个测试脚本全绿。
